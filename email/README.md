# email

アウトバウンドメール送信に関する運用、テンプレート、レビュー基準を置きます。

## 鉄の掟

メール営業では、各社ごとにパーソナライズした文面を必ず入れる。

送信禁止:

- 社名だけ差し替えたメール
- 業界名だけ差し替えたメール
- セミナー内容が本文に接続されていないメール
- 経営ベネフィット、P/Lインパクトがないメール
- 対象企業の具体情報が1つもないメール
- 配信停止、苦情、バウンス、再送禁止の記録を確認していないメール

## 送信基盤・認証手順

- メール送信はSendGridを使用する
- SendGrid APIキーは、リポジトリのローカルGit設定 `adr-seminar-bdr.sendgrid-api-key` から読み取る
- ローカル設定がない場合のみ、ユーザーが送信直前にクリップボードへコピーする
- APIキーの実値を画面、ログ、Markdown、CSV、チャット、配信ログへ表示しない
- APIキーをGit管理ファイルや配信成果物へ保存しない
- Redash APIキーとの取り違えを防ぐため、SendGridキーはローカルGit設定、Redashキーはクリップボードを使用する
- 宛先、件名、本文、送信元、Reply-To、配信停止・苦情・バウンス・重複を送信前に検証する
- 少数テスト送信と結果確認を経てから配信規模を拡大する
- 実送信結果を配信ログ正本スプレッドシートへ記録する

## 必須構成

1. 企業固有の冒頭フック
2. セミナー内容との接続
3. 経営ベネフィット
4. P/Lインパクト
5. 参加すると得られる示唆
6. 申込CTA

## レビュー基準

- 対象企業の公式情報または信頼できる根拠に基づいている
- 読み手の役職と責任範囲に合っている
- 誇張や断定がない
- SalesNow側の都合ではなく、相手企業の意思決定メリットが中心になっている
- 送信ログに送信根拠、配信停止、苦情、次回接触可能日を記録できる
